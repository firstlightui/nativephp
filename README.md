# Firstlight UI

Native controls for NativePHP, shaped for each platform.

Firstlight provides genuine platform controls behind a shared EDGE API. iOS uses UIKit and SwiftUI integration; Android uses Jetpack Compose and Material 3.

[firstlightui.dev](https://firstlightui.dev) · [team@firstlightui.dev](mailto:team@firstlightui.dev)

## Installation

```bash
composer require firstlightui/nativephp
```

Rebuild the native application after installing or updating Firstlight so its platform renderers are compiled into the host app.

## Segmented

Bind a string value with the familiar `native:model` API:

```php
public string $queue = 'mine';

public array $queueOptions = [
    'mine' => 'Mine',
    'all' => 'All',
];
```

```blade
<firstlight:segmented
    :options="$queueOptions"
    native:model="queue"
    label="Queue"
    helper="Choose the active queue."
/>
```

Integer values and disabled choices use rich options:

```php
public int $priority = 10;

public array $priorityOptions = [
    ['value' => 10, 'label' => 'Routine'],
    ['value' => 20, 'label' => 'Urgent', 'disabled' => true],
];
```

```blade
<firstlight:segmented
    :options="$priorityOptions"
    native:model="priority"
    label="Priority"
/>
```

### State timing

Segmented is server-authoritative. A tap emits its change immediately, but the visible selection changes only when PHP publishes the accepted value. If PHP rejects a value by retaining the existing property, the control never displays the rejected selection. Repeated attempts still emit repeated changes.

Use plain `native:model` or `native:model.live`. Deferred `blur` and `debounce` modes are rejected because a segmented selection is an immediate semantic action.

### Options and values

- Values may be all strings or all integers. Mixing types is rejected.
- Values must be unique and must not be inferred from display labels.
- `null` means no selection; an authored empty string remains a distinct string value.
- A selected value that is absent from `options` remains visibly unselected.
- Empty options produce an inert disabled control.

### Props and events

| API | Type | Purpose |
| --- | --- | --- |
| `options` | `array` | Simple, associative, or rich options with `value`, `label`, and optional `disabled`. |
| `value` / `native:model` | `string\|int\|null` | Stable selected value. |
| `label` | `string` | Visible field label. |
| `helper` | `string` | Supporting text below the control. |
| `error` | `string` | Error text and accessibility error state. |
| `required` | `bool` | Marks the field as required. |
| `disabled` | `bool` | Disables the complete control. |
| `a11y-label` | `string` | Explicit accessibility label when a visible label is inappropriate. |
| `a11y-hint` | `string` | Additional VoiceOver and TalkBack guidance. |
| `@change` | callback | Receives the selected stable value. Usually generated by `native:model`. |
| `class` | `string` | External EDGE layout utilities. |

A visible `label` or explicit `a11y-label` is required for an accessible field. Firstlight warns during development when both are blank.
