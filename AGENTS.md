## Learned User Preferences

- Prefer landing Firstlight work by committing and merging straight to `main` rather than opening PRs when asked to ship.
- Keep local planning files out of git; do not commit `roadmap.md` or the mobile-ui gap scratchpad.
- Prefer genuine native platform presentation for dialogs and sheets (benchmark against Confirmation Dialog) over web-like chrome.
- Commit documentation screenshot PNGs under `docs/screenshots/` so the public docs site does not 404.
- Prefer Laravel-shaped SuperNative PHP extensions that reuse existing tags over new catalogue tags when the need is orchestration (validation, submit, authorize, pagination, destructive list actions).
- For Media field design, prefer one catalogue control with `image`/`document` modes, author-controlled crop/`aspect`, and a rich `MediaValue` model rather than a picker-only control.
- When capturing docs screenshots, prefer already-open simulators/emulators rather than launching new devices.
- Prefer continuing feature work inline in the primary checkout when subagent-driven or git-worktree setup is causing friction.
- Prefer package locale chrome next (picker locale/timezone plus Laravel lang for package-owned strings; no translation UI) over a Notification→Feedback bridge.

## Learned Workspace Facts

- Firstlight UI (`firstlightui/nativephp`) exposes a shared EDGE API backed by SwiftUI and Jetpack Compose for NativePHP; public docs are at https://firstlightui.dev.
- Firstlight's publication contract is `FirstlightUI\NativeComponent`: final chrome-wrapped roots carry a private process-wide increasing `firstlight_response_revision`; Blade is automatic, programmatic roots return `$this->response($element)`, nested children and partials are unstamped, and streaming is final-disabled. Use official unpatched Mobile `^4.7.0` / UI `^0.9.0` binaries; #365 remains upstream but is no longer the release dependency. 1.0.0 shipped after physical-device testing, including VoiceOver on iOS; spoken TalkBack and soak/performance evidence are not recorded. Revisions are not per-event acknowledgements or concurrency serialization.
- Catalogue boundary: new `<firstlight:...>` tags only for semantic controls with equal iOS/Android contracts; layout and navigation chrome stay in Mobile UI; Laravel familiarity is delivered via PHP SuperNative extensions.
- SuperNative PHP helpers live as concerns on `NativeComponent` (for example `ValidatesFields`, `SubmitsForms`, `AuthorizesActions`, `PaginatesLists`, `DestroysListItems`).
- Approved Media field is `<firstlight:media>` binding `?MediaValue` (default disk `mobile_public`); image mode uses a Firstlight-owned crop sheet, document mode uses the system file picker.
- Component screenshot evidence belongs at `docs/screenshots/<component>/{ios,android}-{light,dark}.png`.
- `roadmap.md` and `mobile-ui-component-gap-scratchpad.md` are gitignored local planning files.
- iOS and Android simulators are available in the local macOS environment. Debian orbs run PHP, web, Android JVM tests and Android consumer builds; iOS builds and simulator captures need macOS (a Mac satellite from an orb). See Native builds from orbs.
- Firstlight must not POST to FCM from the device; a Notification→Feedback bridge, if resumed, is inbound-only (foreground receive and tap enqueue existing Transient Feedback; no `FeedbackChannel` in v1).

## Native builds from orbs

- **Android runs in the orb.** `.agents/setup` installs Temurin JDK 21, the Android SDK in `~/.local/share/firstlight/android-sdk` (platform 36, build-tools 35, NDK 27.0.12077973, CMake 3.22.1), links `java`, `keytool`, `sdkmanager` and `adb` into `/usr/local/bin` (Amp's `~/.env` replaces PATH), and caps Gradle in `~/.gradle/gradle.properties` so the 8 GB orb is not OOM-killed. Package tests: `tests/android/gradlew -p tests/android testDebugUnitTest` (Robolectric and Paparazzi). Consumer build, in `../repos/showcase`: `php artisan native:install android --no-interaction` once per orb, then `php artisan native:run android --build=release --no-tty`, which writes an unsigned `nativephp/android/app/build/outputs/apk/release/app-release-unsigned.apk` without a device. Orbs have no KVM, so there is no emulator: use a device through a runner or a Bifrost build.
- **iOS runs on a Mac satellite** (`mac_sidecar start`, `macos-27` image; verified with Xcode 27.3). Package tests run in the mirror: `xcodebuild -scheme FirstlightIOSControls -destination 'platform=iOS Simulator,id=<udid>' test` on the iOS 27.0 iPhone 17 Pro that the snapshot references expect. The mirror carries only this checkout, and Showcase's vendor/ needs the orb's plugins.nativephp.com credentials, so for consumer builds run `.agents/mac-setup serve` on the orb, start the Mac with `forward_ports: ["8765"]`, run `.agents/mac-setup` in `mac_shell` (it puts Showcase at `../showcase` next to the mirror), then `.agents/mac-setup stop` on the orb. If Mac commands warn "Not forwarded because the Mac port is taken" and the Mac's `curl` to `127.0.0.1:8765` fails with `(56) Recv failure`, a dropped connection still holds the forward (`lsof -nP -iTCP:8765` shows the satellite's `agent`): call `mac_sidecar start` with `forward_ports: ["8765"]` again, which re-establishes it on the same Mac. In that Showcase run `php artisan native:run ios <udid> --no-tty`, capture with `xcrun simctl io booted screenshot`, and fetch with `mac_download`. After package edits, rerun serve and the Mac step; the copy is a snapshot. Satellite simulators are disposable, unlike the shared local ones the screenshot skills protect.
- **Releases go through Bifrost** (NativePHP Bifrost MCP, team CCMx `346`, project "FirstLight Showcase" `9f60b04a-b1ec-4fc6-a744-82789b7b7f30`, which builds `firstlightui/showcase` `main` and holds the iOS and Android signing credentials). **App Store Connect** (`app_store_connect` tool, workspace key) has the app as `6826403090` "Firstlight Showcase" / `dev.firstlightui.showcase` under team `DH563MAAXU`; use it for TestFlight groups, install links, tester feedback and crash logs. Triggering Bifrost builds, uploading, adding testers and submitting for review all need explicit approval.
